# 一、这个项目是做什么的

这是一个Spring Boot 后端项目，作用是管理一张数据库表里的“用户/任务”数据。

虽然代码中把对象叫做 Task，接口叫 /api/tasks，但你现在保存的数据实际上更像用户：

{
"id": 1,
"title": "王浩宇",
"status": "广州华立学院"
}

可以理解成：

| 代码字段 | 实际含义 |
  |---|---|
| id | 用户编号 |
| title | 用户姓名 |
| status | 用户方向、学校或分类 |

所以这个项目本质上是一个简单的用户信息增删改查接口。

# 二、项目像一间小商店

可以把整个项目想象成一家小商店：

前端/测试工具
↓
Controller 控制器
↓
Service 服务层
↓
Mapper 数据访问层
↓
MySQL 数据库

每一层负责不同事情。

## 1. 前端或请求工具

例如你发送：

GET http://localhost:8081/api/tasks

它就像顾客走进商店说：

> 请把所有用户给我看看。

目前项目里没有真正的 Vue 页面，主要通过 test.http 或 Postman 发送请求。

## 2. Controller 控制器

文件：

D:/HUODUAN/demo/src/main/java/com/example/demo/controller/TaskController.java

Controller 就像商店门口的服务员。

它负责：

- 接收请求
- 读取参数
- 调用 Service
- 返回统一结果

例如：

@GetMapping
public Result<List<Task>> getList(...) {
return Result.success(taskService.findAll(status, title));
}

意思是：

> 有人访问 /api/tasks，我就让 Service 查询用户列表，然后把结果返回。

## 3. Service 服务层

文件：

D:/HUODUAN/demo/src/main/java/com/example/demo/service/TaskService.java

D:/HUODUAN/demo/src/main/java/com/example/demo/service/impl/TaskServiceImpl.java

Service 就像商店里的主管。

它负责：

- 判断业务逻辑
- 查询用户
- 新增用户
- 修改用户
- 删除用户
- 判断用户是否存在

例如修改用户时：

if (baseMapper.selectById(task.getId()) == null) {
return false;
}
return baseMapper.updateById(task) > 0;

意思是：

1. 先根据 ID 找人
2. 如果找不到，返回失败
3. 找到了，再修改信息

## 4. Mapper 数据访问层

文件：

D:/HUODUAN/demo/src/main/java/com/example/demo/mapper/TaskMapper.java

Mapper 就像仓库管理员。

它直接负责和数据库沟通。

现在使用的是 MyBatis-Plus：

@Mapper
public interface TaskMapper extends BaseMapper<Task> {
}

以前要自己写：

selectAll()
selectById()
insert()
update()
deleteById()

还要写 XML。

现在继承 BaseMapper<Task> 后，MyBatis-Plus 已经帮你准备好了常用方法：

selectById()
selectList()
insert()
updateById()
deleteById()

所以 TaskMapper 里面不需要再写一堆方法。

# 五、ID 为什么以前特别大

以前返回：

"id": 2082760393539661826

这是因为 MyBatis-Plus 默认使用雪花算法生成 ID。

雪花算法会生成很长的数字，优点是：

- 分布式系统里不容易重复
- 不依赖数据库自增
- 速度比较快

但是你现在想要的是：

1、2、3、4、5

所以我们加了：

@TableId(value = "id", type = IdType.AUTO)
private Long id;

这表示：

> ID 不由 Java 生成，交给 MySQL 自增。

但是这里有一个重点：

这个设置不会修改数据库里已经存在的旧 ID。

以前已经生成的大 ID 还会保留。数据库自增也会从当前最大 ID 继续增长。

如果想让旧数据重新变成 1、2、3，必须执行数据库迁移 SQL，不能只改 Java 代码。

# 六、当前所有接口

Controller 的统一前缀是：

@RequestMapping("/api/tasks")

所以所有接口都以 /api/tasks 开头。

## 1. 查询用户列表

GET /api/tasks

完整地址：

http://localhost:8081/api/tasks

返回：

{
"code": 200,
"data": [
{
"id": 1,
"title": "王浩宇",
"status": "广州华立学院"
}
],
"msg": "操作成功"
}

还可以传条件：

GET /api/tasks?title=王&status=广州

其中：

- title=王：姓名中包含“王”
- status=广州：方向或学校等字段等于“广州”

———

## 2. 根据 ID 查询用户

GET /api/tasks/{id}

例如：

GET /api/tasks/1

代码会执行：

baseMapper.selectById(id)

如果找到，就返回用户。

如果找不到，就返回：

{
"code": 500,
"data": null,
"msg": "没有找到该用户"
}

———

## 3. 按姓名或方向模糊查询

GET /api/tasks/search

按姓名查询：

GET /api/tasks/search?name=王

按方向查询：

GET /api/tasks/search?direction=广州

两个条件一起查询：

GET /api/tasks/search?name=王&direction=广州

代码使用了：

LambdaQueryWrapper<Task> queryWrapper = new LambdaQueryWrapper<>();

这就像给数据库下条件：

> title 里面包含“王”，并且 status 里面包含“广州”。

对应代码：

queryWrapper
.like(StringUtils.hasText(name), Task::getTitle, name)
.like(StringUtils.hasText(direction), Task::getStatus, direction);

这里：

Task::getTitle

代表数据库字段 title。

Task::getStatus

代表数据库字段 status。

———

## 4. 新增用户

POST /api/tasks

请求体：

{
"title": "王浩宇",
"status": "广州华立学院"
}

注意：新增时不要传 id。

数据库会自动生成 ID。

Service 使用：

baseMapper.insert(task)

———

## 5. 修改用户

PUT /api/tasks/{id}

例如：

PUT /api/tasks/1

请求体：

{
"title": "王浩宇",
"status": "广东科技学院"
}

Controller 会把路径中的 ID 放进对象：

task.setId(id);

然后执行：

baseMapper.updateById(task)

———

## 6. 删除用户

DELETE /api/tasks/{id}

例如：

DELETE /api/tasks/1

Service 执行：

baseMapper.deleteById(id)

# 七、Result 是干什么的

文件：

D:/HUODUAN/demo/src/main/java/com/example/demo/entity/Result.java

Result 是统一包装盒。

不管查询成功还是失败，返回格式都一样：

{
"code": 200,
"data": {},
"msg": "操作成功"
}

其中：

| 字段 | 含义 |
  |---|---|
| code | 状态码 |
| data | 真正的数据 |
| msg | 提示信息 |

成功时：

Result.success(data)

失败时：

Result.fail("没有找到该用户")

这样前端就不用猜每个接口返回的数据格式。

# 八、MyBatis-Plus 是什么

以前查询数据库，要自己写很多 SQL：

select * from task where id = ?

还要写 XML。

MyBatis-Plus 就像一个已经帮你写好常用 SQL 的工具箱。

常用方法：

baseMapper.selectById(id);

根据 ID 查询。

baseMapper.selectList(wrapper);

查询多条数据。

baseMapper.insert(task);

新增数据。

baseMapper.updateById(task);

根据 ID 修改。

baseMapper.deleteById(id);

根据 ID 删除。

这样项目代码更短，也更规范。

# 九、之前遇到的问题总结

## 1. 405 错误

之前请求了：

POST /api/tasks/add
GET /api/tasks/1
PUT /api/tasks/update

但后端接口实际上是：

POST /api/tasks
GET /api/tasks/{id}
PUT /api/tasks/{id}

地址不一致，所以返回 405。

———

## 2. 旧 MyBatis 和 MyBatis-Plus 混在一起

原来有手写 Mapper 和 XML，后来又想使用：

BaseMapper
IService
ServiceImpl

两套方式混在一起，容易出现方法找不到、接口对不上等问题。

现在已经统一成 MyBatis-Plus 架构。

———

## 3. ID 不是从 1 开始

原因是旧数据已经使用雪花算法生成了大 ID。

改成数据库自增后：

@TableId(type = IdType.AUTO)

只会影响新增数据，不会自动修改旧数据。

———

## 4. 前端显示科学计数法

例如：

"id": 2.0827611733991875e+18

这是因为：

- ID 太大
- JavaScript 对超大整数处理不安全
- 浏览器把它显示成科学计数法

最根本的解决方式是把数据库旧 ID 重新整理成较小的数字。

# 十一、目前还可以改进的地方

## 1. 类名不够准确

现在用户数据还叫：

Task
TaskController
TaskService

如果项目正式做用户管理，建议改成：

User
UserController
UserService
UserMapper

接口也可以改成：

/api/users

不过改名会影响前端和已有请求，需要整体修改。

———

## 2. 字段名不够直观

现在：

title = 姓名
status = 方向/学校

别人看代码不容易明白。

更好的字段是：

name
direction

数据库也对应改成：

name
direction

———

## 3. 数据库密码直接写在配置文件

当前配置中有：

password: 123456

学习阶段可以这样写，但正式项目不建议。

更安全的方式是使用环境变量：

password: ${DB_PASSWORD}

———

## 4. 错误状态码可以更规范

当前失败返回：

{
"code": 500
}

但“用户不存在”不一定是服务器错误，更适合使用：

404

参数错误可以使用：

400
